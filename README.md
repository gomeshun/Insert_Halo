Insert_Halo aims to combine the publicly available codes [Sashimi-SIDM](https://github.com/shinichiroando/sashimi-si) and [pyHalo](https://github.com/dangilman/pyHalo) so that dark matter subhalos generated by Sashimi are inserted into pyHalo so that those subhalos can be used for gravitational lensing analysis through pyHalo.
This code is currently in active development, meaning it is not yet finished and will very likely contains bugs

## Reproducible v1.00 environment with uv

The validated runtime targets `Insert_Halo_v1.00`, Python 3.12.14, and Linux
x86_64. Install [uv](https://docs.astral.sh/uv/getting-started/installation/)
0.12.23 (or a later 0.12 release) and Git, then run from the repository root:

```bash
uv sync --locked
uv pip check
uv run --locked pytest -m integration --durations=1
```

`uv sync --locked` creates an isolated `.venv` and checks that `uv.lock` matches
`pyproject.toml`. It uses `.python-version` to select Python 3.12.14 and can
download that interpreter if it is not installed. The first sync requires network
access to PyPI, GitHub, and, if needed, uv's Python distributions. No previously
configured virtual environment or local dependency checkout is required. For this
validated environment, use the uv configuration rather than the older, unpinned
`requirements.txt`.

The scientific runtime pins NumPy 1.26.4, SciPy 1.13.1, Astropy 7.2.3,
lenstronomy 1.13.2, Numba 0.61.2, Colossus 1.4.0, mcfit 0.0.22, and numexpr
2.14.2. `uv.lock` fixes the full dependency graph and registry artifact hashes.
`pyproject.toml` also constrains transitive dependencies. Source distributions
build in isolation with setuptools 68.2.2 (required by pyHalo), wheel 0.45.1,
and packaging 26.3; the runtime dev tools remain setuptools 84.0.0 and wheel
0.48.0. The two Git dependencies use immutable revisions:

| Dependency | Version | Commit |
| --- | --- | --- |
| pyHalo | 1.4.6 | `91a5d39aa6b23f4a71d670f32cb21b12a29b7c9a` |
| samana | 0.2.0 | `723e009de9d7544f33e78f40a3978f09f57787ae` |

These versions preserve the APIs used by the original code: the ModelPlot
`arrow_size`/`cmap_string` arguments, samana's five-item `setup_kwargs_model`
return, and pyHalo's CDM preset arguments. SciPy 1.13.1 also supports the
positional `simpson(y, x)` calls in v1.00. Use `--locked` for routine runs;
updating dependencies requires another end-to-end verification.

The pytest integration test in `tests/test_environment_integration.py` runs
the original WGD2038 PSO (10 particles, 100 iterations), initializes the fitted
image model, and completes five reduced SIDM
ABC trials, including summary statistics and selection of the best 20%. It always
fits from scratch. It selects v1.00 explicitly so the older modules in the
repository root cannot shadow it. The existing `setup_data_modelplot()` method
solves the linear brightness amplitudes before image rendering.

The reduced ABC configuration uses halo masses from 10^7 to 10^9 solar masses,
50 Gaussians, and SASHIMI `dz=0.1`, `N_ma=30`, `N_herm=4`, `zmax=3`. It is a
runtime check, not a full thesis reproduction or a converged SIDM constraint.
The research modules and their physical assumptions are unchanged. These pins
describe a working compatibility environment; the original thesis dependency
versions were not recorded.

The test configures a headless plotting backend, numerical thread limits, and
the supported Colossus cache directory setting without modifying library APIs or
the research modules. Caches and `result.json` are written under ignored `work/`
directories. An exception or invalid numerical output produces a nonzero exit
status and an error report.
On a 4-CPU Cloud environment, expect roughly 3–4 minutes for the verification,
excluding dependency installation. Reports, fits, and research results are not
committed.

The thesis-scale run (200 ABC realizations, six 300×300 convergence maps, and
supplementary diagnostics) is documented in
[`scripts/full_run/README.md`](scripts/full_run/README.md).

`.github/workflows/uv-integration.yml` runs the same locked installation,
dependency check, and integration test on every push and pull request. It can
also be started manually. The workflow uses Ubuntu 24.04, uv 0.12.23, a fresh
virtual environment, and a 20-minute timeout. Only uv's download/build cache is
reused; the PSO fit and ABC trials run afresh. The job has read-only repository
permissions and does not upload numerical reports as artifacts.
